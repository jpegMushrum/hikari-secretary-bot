# Продолжение черновика в Mini App

Подготовка сообщения остаётся в Telegram. Администратор пересылает/отправляет
сообщение боту, который сохраняет публикацию в backend как раньше.
Все кнопки выбора целей, регистрации, немедленной отправки и отложки сохранены.

Опциональная переменная `MINIAPP_URL=https://club.example` добавляет к
черновику кнопку «Продолжить в панели». Только HTTPS origin, без пути/query/
fragment/учётных данных. Кнопка открывает `/admin/publications/{id}` в WebApp;
права проверяются Go backend по настоящему Telegram initData. ID черновика
в ссылке сам по себе не даёт доступа. Кнопка появляется только в уже
защищённом административном flow; пользовательские меню не меняются.

Без MINIAPP_URL ничего дополнительно настраивать не нужно, работает старый
flow. На локальном dev-стенде бот не запускается, кнопку localhost в Telegram
не настраиваем. HTTPS и ручная проверка Telegram нужны перед отдельным релизом.

В miniapp администратор видит read-only preview и настраивает событие, цели,
немедленную отправку или отложку. Исходные Telegram entities/rich_message
не редактируются; backend хранит один черновик для обоих интерфейсов.

Для preview rich-фото бот скачивает локальные копии в MEDIA_DIR. В отправку
rich message по-прежнему идут исходные Telegram file IDs. Сбой скачивания
preview не блокирует создание/отправку сообщения, в stdout появляется warning.
Backend читает MEDIA_DIR через BOT_MEDIA_DIR; в стандартном compose оба
сервиса видят `/app/data/media` в общем volume.

После отмены или отправки фото сохраняются для просмотра истории. Retention
нужно планировать отдельно; не удаляйте общий media volume при пересборке.
Дальнейшие улучшения UX бота и замена содержимого существующего черновика
через отдельный диалог — последующие задачи; текущий fallback не заменяется.

Unit-тесты: `python -m unittest discover -s tests` из каталога bot.
