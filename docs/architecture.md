# Архитектура Telegram-бота

Python-процесс на `aiogram` получает обновления Telegram через polling и
доставляет сообщения. Go backend обслуживает внутренний API, применяет
бизнес-правила и хранит данные в PostgreSQL. Через отдельный Admin API с теми же
данными работает miniapp.

## Запуск и обработка обновлений

`app/main.py` загружает настройки и запускает `SecretaryBot` из `app/bot.py`.
Он создаёт клиент backend и Telegram, регистрирует обработчики, настраивает
команды и персональные кнопки администраторов. При остановке он завершает
фоновый цикл и закрывает HTTP-сессии.

Обработчики находятся в `app/handlers/`:

- `core.py` — главные меню, команды и ссылки для регистрации на мероприятие.
- `publications.py` — приём материалов, сбор альбомов, черновики, выбор целей
  и времени отправки.
- `registrations.py` — профили, регистрации, посещаемость, отзывы,
  административные списки.
- `ai_topics.py` — настройки ИИ, предпросмотр и управление темами в очереди.
- `inbox.py` — маршрутизация текста, фото и Telegram Rich Messages, которые
  не обработали команды. Сначала проверяется незавершённый пользовательский
  диалог, затем ввод для ИИ, затем ввод параметров публикации или нового материала.

`app/keyboards.py` собирает кнопки, `app/presentation.py` формирует таблицы
и другие представления для Telegram.

## Хранение и API

`BackendClient` и `BackendDatabase` в `app/backend.py` преобразуют операции
бота в HTTP-запросы с `BOT_SERVICE_TOKEN`. Backend хранит публикации,
профили, регистрации, отзывы, очередь доставки и задания ИИ. Проверка лимитов
на backend применяется и к запросам вне меню бота. В `RuntimeState` остаются
временные шаги диалогов и предпросмотры.

Содержимое черновика доступно боту и административной панели. Для просмотра
фотографий backend читает общую директорию медиа. Бот также хранит рядом с
`MEDIA_DIR` служебный список чатов, где требуется обновить персональную
кнопку «Панель клуба». SQLite используется при переносе данных со старой версии
платформы.

## Фоновые операции

`SchedulerWorker` запрашивает у backend задания доставки и уведомления,
отправляет их через Telegram и сообщает результаты. Цикл обрабатывает также
напоминания, запросы о посещении и уведомления об окончательном сбое генерации
ИИ. Для аварий доставки отдельным получателям используются результаты и
повторные попытки по соответствующим заданиям.

Backend запускает автоматическую генерацию тем, если она настроена, и
передаёт готовые материалы в общую очередь. `DailyTopicService` и
`DailyTopicRepository` бота работают с ИИ через backend API. Подробнее в
[руководстве по ИИ-материалам](ai-materials.md).

## Правила расширения

Новые диалоги регистрируйте до общего обработчика `InboxHandlers`. Прикладные
операции и их долговечное состояние добавляйте в backend, а обращение к ним
из бота проводите через внутренний API. Изменённые маршруты и переходы
диалога проверяйте тестами с подставными ответами Telegram и backend.

Если в будущем появится проверка японского текста в заданном топике,
фильтруйте сообщения по паре `chat_id` и `message_thread_id` через
`Target.matches()`.
