# Telegram-бот

В составе платформы применяй также корневой `AGENTS.md`.

## Реализация

- Бот на Python/aiogram отвечает за Telegram UI, приём сообщений и доставку.
  Бизнес-правила и данные принадлежат backend; не добавляй прямые обращения
  к PostgreSQL или новое рабочее хранилище SQLite.
- Сохраняй действующие диалоги и кнопки как самостоятельный flow.
  Передача черновика в miniapp не должна блокировать работу через бота.
- При работе с rich messages сохраняй entities, медиа и переносы строк.
- Обрабатывай ожидаемые ошибки доставки так, чтобы один недоступный чат
  не останавливал остальные задания. Логи не должны содержать секреты.

## Проверки

- При установленных зависимостях из этого каталога:
  `python -m unittest discover -s tests -v`.
- Контейнерный вариант запуска указан в `docs/testing.md`; запускай команду
  тестов вместо polling-процесса и не поднимай лишние сервисы.
- В тестах заменяй реальные Telegram API и backend управляемыми подставными
  ответами. Проверяй ошибки backend, callback и изменённые переходы диалогов.
- Проверяй контракт с backend при изменении запросов и форматов ответов.
- Ручную проверку в настоящем Telegram выполняет пользователь, если отдельно
  не поручил её агенту. Unit-тесты не считай такой проверкой.

## Документация и делегирование

- Изменения диалогов отражай в руководствах `docs/`, настройки — в инструкции
  запуска и примерах env. README оставляй кратким описанием компонента;
  основные сведения о клубе и платформе принадлежат корневому репозиторию.
- Для существенных изменений поручай субагентам ревью diff и обновление
  затронутых руководств после реализации. Не допускай совместного
  редактирования одних файлов несколькими агентами.
- Для документации используй `gpt-6.2-sol` с уровнем `low`.
- Для обычного ревью используй `gpt-6.2-sol` с уровнем `medium`.
- Только для сложного ревью миграций, авторизации или очередей используй `gpt-6.2-astra` с уровнем `medium`.
- Если выбранная модель недоступна, сообщи об этом и выполни задачу главным агентом. Другую модель используй только по указанию пользователя.
- Изменения записывай в «Не выпущено» CHANGELOG; версии не придумывай.
